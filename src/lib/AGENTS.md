# src/lib rules

- OMNI agent memory is owner/aal2-only, one agent per RPC call, no direct table reads, metadata-only append-only audit; no agent or Railway reads it, why: no cross-agent leakage or external-memory claims.
- The cloud shell relays only to the separate `OMNI_SANDBOX_*` service (never the Jackboy host or secret); sessions need a proof-checked passing sandbox self-test <24 h, every command waits for owner `step.decide`, why: Railway owns execution and the browser holds no credentials.
- Autonomous Mode opens only when every `autonomyGates` gate passes from recorded proof-checked evidence, including a non-null reviewed `AUTONOMY_VERIFIED_RELEASE`; the database also refuses Jackboy, non-15/30/60 windows, stop/kill/paused states and ends windows on them, why: readiness must be proven live before any unattended run.
- OMNI CODE queue (`omni-code-queue.ts`) and Mac file plans (`omni-file-plan.ts`) are pure models plus service-written, owner-read tables (0048) whose triggers refuse leases while always-on is off/expired (≤24 h), Stop/kill switch/pause, unapproved file changes or Jackboy; plans are frozen dry runs with per-step destructive confirmation and a journal for undo, why: always-on means processing authorized jobs, never standing shell or file authority.
- Razul provisioning (`razul-provisioning.ts`, 0050) treats manifests as immutable proposals: approval/widening/promotion need owner + fresh TOTP and a proof-verified sandbox pass of the exact digest, releases change only by promotion/rollback, knowledge is per-namespace, why: Razul must never grant, install secrets or update production by itself.
- Orb voice UIs are frontends only: the terminal orb talks solely through the existing `omni-workspace` relay and names speakers from enrolled `omni_agents` rows; the `/beta-omni` orb uses `/api/omni-agent` and is labelled as the Mothership text agent; `omni-voice.ts` owns routing/labels and unconnected agents are announced as not connected, why: no new AI backend, and a speaker name must never imply a connection.
- OMNI private chat (`omni-chat.ts`) shows history from the owner's saved `omni_agent_runs` only; earlier turns reach the model only via per-request `contextTurns` (0–6, default 0, server re-reads and fails closed); model picker lists only server-configured providers; handoffs go through the owner-only `queueTerminalTask` as held tasks after explicit approval, why: no new store, no silent context and no execution from chat.
- Activation Approvals are ordered owner records written only through a fresh-TOTP (≤15 min) owner RPC with cascade reset and audit; approvals decided before the owner's latest security reset (two-step off, recovery, admin factor removal) count as pending in `activation-status.ts` and every server function; the page lists rows even when the check store is absent and names the exact access reason, why: a recorded approval is evidence, not execution, and must not survive a credential reset.
