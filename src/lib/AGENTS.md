
- The Jackboy link client uses platform `fetch` with public-certificate validation, refused redirects, bounded replies/timeouts and public-HTTPS-origin checks; no custom CA or insecure TLS option, why: this hosting cannot load CA files and verification must never be disabled.
- Held OMNI Terminal tasks reach Jackboy only via the owner-triggered signed `jackboy.omni-handoff/v1` call (mirrors Jackboy's contract exactly; owner-entered Jackboy project id; fresh TOTP, Stop released, server-verified signed replies recorded service-only); Mothership never dispatches to OMNI or approves Jackboy jobs, and docked devices only read their own statuses, why: Jackboy stays the passkey/spend gatekeeper.
- Activation Approvals: a technical-step check only records evidence (or a failure); the owner approves separately with fresh MFA, within the database's 15-minute fresh-pass window; approved steps refuse re-checks and duplicate approvals server-side; link failures carry only a stage, HTTP status and allowlisted Jackboy refusal code, why: a passing check must never approve for the owner, and diagnoses must not leak reply contents.
- Activation Approvals build labels come from `approval-flow-build.ts`: bump `APPROVAL_FLOW_VERSION` when the approvals screen or rules change; the public `/api/public/approval-flow` marker returns only that number and the preview compares it server-side (fixed live URL, no redirects, bounded), treating a missing marker as an earlier flow and unreachable as unknown, why: a version marker shows which screen a site serves, never approval or readiness.
- Jackboy link deadlines come from `linkTimeoutMs`: actions where Jackboy itself waits on the Railway runner (configuration, run) must stay longer than Jackboy's own wait plus headroom; timeouts record the deadline, wait and phase, why: Mothership must never give up before Jackboy can send its signed, classified answer.
- Activation Step 8's "Run protocol self-test & verify" (`runStep8SelfTest`) is the only approvals action that sends the fixed self-test: owner + fresh MFA + per-click `confirm`, fail-closed readiness (Emergency Stop, link/self-test switches, approval window, identity reported per setting name with no aliases), and a client attempt ID whose audit trail decides the stage so a retry only reads status and never resubmits/reruns; results become evidence only, why: proof must be real and one authorization must never run twice or approve.

Emergency Stop) with no job, self-test or CODE; Step 10 records cap confirmations only and CODE status is always "off" because Mothership has no CODE path; Jackboy's Kill Switch/CODE stop are never read or changed here, why: connection diagnostics must stay independent of execution authority.
- Jackboy safety (`jackboy-safety*.ts`, migrations 0053/0054): only a fresh signed `safety-state` poll may record "clear"; signed `jackboy.safety-event/v1` notices may only record a stop; failures/stale record "unknown".
